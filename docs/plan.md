# 実装計画（単独 PC 版）

作成日：2026-11-10 ・ 更新日：2026-11-10（未決事項をすべて決定し、Claude Desktop を加えた）

## 目的

1 台の PC の中で動いている Claude Code の複数のセッションを、同じ PC のブラウザから一覧で見守れるようにします。

複数の PC からサーバーへ送る前身の仕組みを、1 台の PC の中で完結する形に作り変えます。

## 要件

| # | 要件 |
| --- | --- |
| 1 | 1 台の PC で動いている Claude Code の複数のセッションを監視できる |
| 2 | 起動元ごとにまとめて表示する。ターミナルの Claude Code と VS Code の Claude Code を見分けられる |
| 3 | 各セッションのプロンプトと、それに対する応答を見分けられる。どの応答がどのプロンプトへのものかが分かり、混線しない |
| 4 | セッションをクリックすると、詳しい履歴を表示する |

要件をもとに、次のとおり決めました。

| 項目 | 決定 |
| --- | --- |
| 応答として表示するもの | プロンプトごとに、最後の文章だけ。途中の文章・ツールの実行・考え中の内容は表示しない |
| 表示するセッション | 起動中のものだけ |
| 画面を見る場所 | 同じ PC のブラウザ（`localhost`）だけ |
| 残す機能 | 利用枠の表示、アラート（放置・ファイル競合・危険操作）、オフィス表示、Codex CLI の検知、Remote Control への導線 |
| 外す機能 | 画面のログイン、プッシュ通知、物理表示灯（M5Stack）、複数の PC の登録（PC ごとのトークン）、macOS 用の常駐の仕組み（`deploy/macos/`） |
| 対象の OS | Windows 11 だけ。OS に依存する処理（親プロセスの調べ方など）は 1 か所にまとめる |
| 監視サーバーの起動 | Windows にサインインしたときに自動で起動する（タスク スケジューラに登録） |
| エージェントからの送信の認証 | PC ごとのトークンはなくす。代わりに、リクエストの `Host` と `Origin` が `localhost` 以外なら断る（下の「セキュリティ」を参照） |
| データの保存 | 会話の本文は保存しない。保存するのは利用枠の記録・費用の記録・アラートだけで、保存期間は 15 日 |
| ファイルの読み方 | 1〜2 秒ごとに読み直す。`sessions` フォルダは毎回全部、会話記録は大きさが変わったファイルだけを前回の続きから読む。ファイル監視は Windows で取りこぼしが起きることがあるため使わない |

## 全体構成

手元で動くサーバーが、Claude Code が PC に残しているファイルを直接読みます。Claude Code の hooks に登録するのは、ファイルからは取れない「利用枠」と「危険操作のガード」の 2 つだけです。

```text
┌──────────────────────────── 1 台の PC ────────────────────────────┐
│                                                                    │
│  Claude Code（VS Code の拡張・VS Code のターミナル・Windows Terminal・Claude Desktop）│
│    │ 書き出す                          │ 呼び出す                      │
│    ▼                                   ▼                             │
│  ~/.claude/sessions/<pid>.json       statusLine・利用枠の mod          │
│  ~/.claude/projects/…/<id>.jsonl     PreToolUse フック（危険操作のガード）│
│    │ 読む                              │ 送る（127.0.0.1）              │
│    ▼                                   ▼                             │
│  ┌──────────────── 監視サーバー（127.0.0.1 だけで待ち受け） ───────────┐  │
│  │ セッション一覧・会話の読み取り・アラート判定・利用枠の受信            │  │
│  └──────────────────────────┬───────────────────────────────────┘  │
│                             │ WebSocket                            │
│                             ▼                                      │
│                   ブラウザ（http://localhost:<port>）                 │
└────────────────────────────────────────────────────────────────────┘
```

| 部品 | 役割 | 前身からの変更 |
| --- | --- | --- |
| 監視サーバー | `~/.claude/sessions` と会話記録を読み、状態・会話・アラートを作って画面へ配信する | hooks の受信を中心にした作りから、ファイルを読む作りに変える |
| PC 側のエージェント | statusLine・利用枠の mod・PreToolUse フックから呼ばれ、利用枠と危険操作の判定結果を監視サーバーへ送る | セッションのイベントを送る役目はなくす |
| 画面 | 一覧・詳細・オフィス表示・利用枠・アラート | ログインをなくす。まとまり（起動元）ごとの表示と、会話の履歴を加える |

## 情報源

### `~/.claude/sessions/<pid>.json`

起動中の Claude Code 1 つにつき 1 ファイルあります。公開されていない内部用のファイルです。Windows 11 で、Claude Code 2.1.319（VS Code の拡張・ターミナル）と 2.1.321（Claude Desktop）の中身を確かめました。

| 項目 | 内容 | 使い道 |
| --- | --- | --- |
| `pid` | Claude Code のプロセス ID | 起動中かどうかの判定、親プロセスをたどる起点 |
| `sessionId` | セッション ID | 会話記録のファイル名と対応づける |
| `cwd` | 作業フォルダ | 一覧の表示 |
| `entrypoint` | 起動元（VS Code の拡張は `claude-vscode`、ターミナルは `cli`、Claude Desktop は `claude-desktop`） | まとまりの判定 |
| `status` | `busy`（作業中）・`idle`（入力待ち）・`waiting`（ダイアログで答えを待っている） | 状態の表示、放置アラート |
| `waitingFor` | `status` が `waiting` のときだけ出る。許可ダイアログは `permission prompt`、質問ダイアログは `input needed` | 待ちの内容の表示 |
| `name` | セッションの表示名（例：`claude-dashboard-mono-84`） | 一覧の表示 |
| `bridgeSessionId` | `/remote-control` が有効な間だけ書かれる。Claude Desktop では最初から入っていた（Desktop の設定によるものかは未確認） | Remote Control の URL（`https://claude.ai/code/<bridgeSessionId>`） |

`status` の動きは、実際に操作して確かめました（2026-11-10）。

| 操作 | `status` | `waitingFor` |
| --- | --- | --- |
| プロンプトを受け付けた | `busy` | — |
| 応答を終えた（文章で質問を返した場合も含む） | `idle` | — |
| 質問ダイアログ（AskUserQuestion）を出した | `waiting` | `input needed` |
| 許可ダイアログ（ファイルの書き込み）を出した | `waiting` | `permission prompt` |

### 会話記録（`~/.claude/projects/<フォルダ>/<sessionId>.jsonl`）

1 行が 1 件の記録です。プロンプトと応答の対応づけに、次の項目を使います。

| 項目 | ある記録 | 使い道 |
| --- | --- | --- |
| `promptId` | `type` が `user` の記録 | プロンプトの識別 |
| `uuid`・`parentUuid` | `user`・`assistant` の記録 | 応答がどの記録への返事かをたどる |
| `isSidechain` | `user`・`assistant` の記録 | サブエージェントの記録を本筋から外す |
| `message.content` | `user`・`assistant` の記録 | 本文。`text`・`tool_use`・`tool_result`・`thinking` の区画からなる |
| `message.model` | `assistant` の記録 | モデルの表示 |

### 親プロセス

`entrypoint` だけでは、VS Code の中のターミナルと Windows Terminal を見分けられません。そこで `pid` から親プロセスをたどります。Windows 11 で確かめた結果は次のとおりです（2026-11-10）。

| 起動元 | 親のたどり方 | 窓を見分けられるか |
| --- | --- | --- |
| VS Code の拡張 | `claude.exe` → 窓ごとの拡張機能用の `Code.exe` → VS Code 本体 | できる。同じ窓のタブは同じ親、別の窓は別の親になった |
| VS Code の中のターミナル | `claude.exe` → シェル → ターミナル用の `Code.exe` → VS Code 本体 | できない。2 つの窓のターミナルが、同じターミナル用の `Code.exe` を共有していた |
| Windows Terminal | `claude.exe` → シェル → `WindowsTerminal.exe` | できない。2 つの窓と 2 つのタブが、同じ `WindowsTerminal.exe` の下にあった |
| Claude Desktop | `claude.exe`（Desktop が自分で持っている Claude Code の本体）→ Desktop の本体（`claude.exe`） | 見分ける必要がない。Desktop の窓は 1 つ |

## 画面

### まとまり（要件 2）

| まとまり | 判定 | 分け方 |
| --- | --- | --- |
| VS Code（拡張） | `entrypoint` が `claude-vscode` | 窓ごと（親の拡張機能用プロセスの pid）。見出しは、その窓のセッションの作業フォルダから付ける |
| VS Code ターミナル | `entrypoint` が `cli` で、親をたどると `Code.exe` に着く | 1 つにまとめ、作業フォルダを並べる |
| Windows Terminal | `entrypoint` が `cli` で、親をたどると `WindowsTerminal.exe` に着く | 1 つにまとめる |
| Claude Desktop | `entrypoint` が `claude-desktop` | 1 つにまとめる |
| そのほか | 上のどれにも当たらない | `entrypoint` の値ごとにまとめる |

### 一覧

まとまりごとにセッションを並べます。各セッションには、表示名・作業フォルダ・状態（作業中・入力待ち・許可待ち・回答待ち）・モデル・直近のプロンプトを出します。オフィス表示では、前身の「PC＝部屋」を「まとまり＝部屋」に置き換えます。

### 詳細と履歴（要件 3・4）

セッションをクリックすると、そのセッションの会話をプロンプトごとに区切って、古い順に表示します。

- 1 つの区切りは「プロンプト 1 件」と「それに対する最後の応答の文章」の組です。
- 組み合わせは、会話記録の `promptId`・`uuid`・`parentUuid` でたどって決めます。時刻の順番だけでは決めません。
- 応答がまだないプロンプト（作業中）は、「作業中」と表示します。
- Claude Code が自動で送る知らせ（バックグラウンドの作業の終了など）と、サブエージェントの記録（`isSidechain`）は、人のプロンプトとして数えません。

## アラート

| アラート | 判定 | 前身からの変更 |
| --- | --- | --- |
| 放置 | `status` が `waiting` のまま 10 分以上続く | Notification フックではなく、`sessions/<pid>.json` で判定する |
| ファイル競合 | 同じファイルを、10 分以内に 2 つ以上の担当（セッション・サブエージェント・Codex CLI）が編集した | 会話記録の `tool_use`（Edit・Write など）から判定する |
| 危険操作 | PreToolUse フックで、エージェントが手元で判定する。当たれば Claude Code の許可ダイアログに回し、監視サーバーに知らせる | 変更なし。送り先が手元の監視サーバーになるだけ |

プッシュ通知は外すので、アラートは画面だけに出します。

## 利用枠

statusLine（ターミナル）と利用枠の mod（VS Code の拡張・Claude Desktop）から届く値を表示します。Claude Desktop で mod から値が届くかは、まだ確かめていません（前身で確かめたのは VS Code の拡張と `claude -p`）。値の取り方は前身と同じで、送り先が手元の監視サーバーになります。上限予測と消費内訳も残します。

## Codex CLI の検知

前身の判定（[packages/shared/src/players.ts](../packages/shared/src/players.ts)）を使い、hooks のイベントの代わりに、会話記録のシェルの `tool_use`（Bash・PowerShell）に当てます。サブエージェントも、会話記録の Agent ツールの呼び出しから検知します。

## セキュリティ

| 観点 | 対策 |
| --- | --- |
| 接続 | 監視サーバーは `127.0.0.1` だけで待ち受け、ほかの端末からは接続できないようにする。画面のログインはなくす |
| エージェントからの送信 | PC ごとのトークンはなくす。同じ PC の同じユーザーで動くプログラムは、トークンを入れた設定ファイルも会話記録も読めるため、トークンを残しても守りはほとんど強くならない |
| ほかの Web サイトからのアクセス | ブラウザで開いたほかのサイトから `localhost` へ送信されたり、会話の中身を読み取られたりしないよう、リクエストの `Host` と `Origin` が `localhost` 以外なら断る（DNS リバインディング対策） |
| 機密情報 | プロンプトや応答の中のトークン・パスワードらしい文字列は、前身と同じく伏せ字にしてから表示する |
| 保存 | 会話の本文は会話記録から都度読み、監視サーバーには保存しない。保存するのは利用枠の記録・費用の記録・アラートだけで、15 日で消す |

## 進め方

| 段階 | 内容 | 次へ進む条件 |
| --- | --- | --- |
| 1 一覧 | 監視サーバーを手元で動かし、`sessions/<pid>.json` と親プロセスからまとまりごとの一覧を出す。ログイン・プッシュ通知・物理表示灯・PC の登録・`deploy/macos/` を外し、`Host`・`Origin` の確認を入れる。サインイン時の自動起動を用意する | VS Code の拡張（2 つの窓）・VS Code ターミナル・Windows Terminal・Claude Desktop のセッションが、正しいまとまりに出る。サインインし直すと監視サーバーが起動している |
| 2 詳細と履歴 | 会話記録からプロンプトと応答の組を作り、詳細に表示する | 応答待ちの間に次のプロンプトを入れた場合などでも、組が正しい |
| 3 アラート・利用枠・オフィス表示 | 放置・ファイル競合を新しい判定にする。危険操作のガードと利用枠の送り先を手元にする。オフィス表示をまとまりごとにする | 放置アラートが許可待ち・回答待ちで出て、普通の入力待ちでは出ない |
| 4 Codex CLI・Remote Control | 会話記録からの検知と、`bridgeSessionId` からの導線 | Codex CLI の実行がプレイヤーとして表示される |

## リスク

| リスク | 内容 | 対応 |
| --- | --- | --- |
| 内部ファイルの変更 | `sessions/<pid>.json` と会話記録は公開された仕様ではない。Claude Code の版が変わると、項目の名前や値が変わる可能性がある | 読み取りを 1 か所にまとめ、読めない項目があっても画面全体は止めない。確かめた版（2.1.319・2.1.321）を記録する |
| 版のずれ | Claude Desktop は Claude Code の本体を自分で持っていて、VS Code の拡張・ターミナルと版がずれることがある（確かめたときは 2.1.321 と 2.1.319） | 項目がないときも読めるようにし、版ごとの違いが見つかったら読み取りの 1 か所で吸収する |
| VS Code の作りの変更 | 窓ごとの判定は、拡張機能用のプロセスが窓ごとに分かれていることに頼っている | 判定できないときは、セッションごとの表示にする |
| 大きな会話記録 | 長いセッションの会話記録は大きくなる | 前回読んだ位置から続きだけを読む |
